## Полиморфизъм
- едно име на функция, много различни имплементации
- Compile time полиморфизъм
- Run time полиморфизъм


## Статично и динамично свързване

- свързването (binding) е процесът, който се използва за преобразуване на идентификатори (например имена на променливи и функции) в 

### Статично свързване
- изборът на функцията, която трябва да се изпълни, става **по време на компилация** (Compile time)
- избира се от указателя/референцията, от която се извиква функцията

### Динамично свързване
- изборът на функцията, която трябва да се изпълни, става **по време на изпълнение на програмата** (Run time)

## Compile time polymorphism
- при компилацията на програмата е ясно коя функция ще се извика

### Function overloading

```c++
void f();
void f(int n);
void f(MyString str);
```

### Operator overloading
```c++
3 + 4
"abc" + "xyz"
```

Пример:

```c++
#include <iostream>

class Base {
public: 
  void f() const  {
		std::cout << "Base::f()" << std::endl;
  }	
};

class Derived : public Base {
public:
  void f() const {
		std::cout << "Derived::f()" << std::endl;
  }	
};	

int main() {
    Derived* der = new Derived();
	Base* base = der;
	
    base->f(); // Base::f()
    der->f(); // Base::f()
}
```


## Runtime Polymorphism
- често се осъществява чрез указатели към функции (в контекста на ооп - виртуални)
- малко по-неефективно, тъй като включва допълнителни нива на пренасочване, но по-гъвкаво

```c++
#include <iostream>

class Base {
public: 
    virtual void f() const  {
		std::cout << "Base::f()" << std::endl;
    }	
};

class Derived : public Base {
public:
    void f() const override {
		std::cout << "Derived::f()" << std::endl;
    }	
};	

int main() {
    Base* base = new Base();
    Base* der = new Derived();

    base->f(); // Base::f()
    der->f(); // Derived::f()
}
```

### Виртуални функции
- виртуалните функции са член-функции, чието поведение може да бъде предефинирано в производните класове
- ако наследник се обработва с помощта на указател или референция към базовия клас, извикването на предефинираната виртуална функция ще извика поведението, дефинирано в наследника
- използват се главно за постигане на Runtime polymorphism

### Особености 
- не могат да бъдат статични
- ако една функция е декларирана като виртуална в базовия клас, то тя остава виртуална и в наследника, независимо дали се предефинира
- не е необходимо функцията в базовия клас да е достъпна, за да бъде предефинирана

- Ако функцията `Derived::f` предефинира функция `Base::f`, техните типове на връщане трябва да са еднакви или да са ковариантни, т.е.
и двата типа са указатели или референции към класове и типът на връщане на `Derived::f()` трябва да еднакво или по-конкретен от типа на връщане на `Base::f()`
- Когато се прави извикване на виртуална функция, типът на върнатия указател се конвертира имплицитно към типа на връщане на базовата функция

### override
- override указва, че дадена функция презаписва функция от базовия клас
- ако в базовия клас няма такава функция, то кодът няма да се компилира.

### final
- final указва, че дадена функция не може да се презависва надолу по йерархията или че даден клас не може да се наследява

## Абстрактен клас
- **чисто виртуална функция** (абстрактна функция) - функция, която няма имплементация

```c++
class Base {
    virtual void f() = 0;
}
```
- **абстрактен клас** - клас, предназначен за наследяване
- не може да се създаде обект от него
- съдържа поне една абстрактна функция
- всеки наследник трябва да разпише имплементацията
- ако някой наследник не я имплементира, и той става абстрактен

- при полиморфна йерархия винаги трябва да имаме **виртуален деструктор**, дори да нямаме динамична памет
